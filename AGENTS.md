# AGENTS.md

Early-warning financial-risk tool for US listed companies. Product spec: `Feuille de route — Détecteur de risque financier.md`; user-facing overview and baseline metrics: `README.md`; deployment runbook: `docs/DEPLOY.md`.

## Working agreements

- **The user implements, the agent reviews/explains.** Give exact commands and detailed reasoning; do not implement features unless explicitly asked.
- Code identifiers and commit messages in **English**; comments, docstrings and user-facing prose in **French**. Detailed explanatory comments are wanted.
- Frontend = Next.js + pnpm + Tailwind, not HTMX. Backend = FastAPI JSON for product data; Next renders product pages. Raw SQL via psycopg, no ORM.
- LSTM signals sit beside classic scores, outside the composite and classic backtest. Changing that requires a full comparative backtest.

## Environment

- Windows + PowerShell; Python **3.14**, `uv`, `pyproject.toml` + `uv.lock`. Run Python from the repo root with `uv run …`; use `python -m …`, not script paths.
- For local setup, `Copy-Item .env.example .env` (real environment variables also work). `app.config.settings` is created at import and reads `.env` relative to the cwd; `DATABASE_URL` and `SEC_USER_AGENT` are required to import the backend, even though public API routes make no SEC requests. Use a real name + e-mail before SEC calls.
- Local PostgreSQL 17 runs in Docker on **host port 5435**, not 5432; local `DATABASE_URL` must use `localhost:5435`.
- `uv sync` removes packages absent from the lockfile. Restore notebook-only deps afterward with `uv pip install tensorflow==2.22.0rc0 ipykernel nbformat`; `calculate_risk.ipynb` imports TensorFlow and uses the `.venv (3.14.3)` kernel.
- `frontend/` is a separate pnpm package: `pnpm --dir frontend install`. Before frontend edits, read `frontend/AGENTS.md` and the relevant bundled docs under `frontend/node_modules/next/dist/docs/`; the former is regenerated by `next dev`.
- Clerk keys belong in ignored `frontend/.env.local`; `WATCHLIST_API_SECRET` must match the backend `.env`, contain at least 32 random characters, and never use a `NEXT_PUBLIC_` name. Set `FRONTEND_ORIGINS` to the deployed Next origin for browser-to-API calls.
- If torch must be re-added, use `uv add torch --index https://download.pytorch.org/whl/cpu --index-strategy unsafe-best-match`; the strategy flag is also needed when adding shap. The CPU index is already declared in `pyproject.toml`.

| DB up | `docker compose up -d --wait` |
| Reset local schema | `docker compose down -v` then `docker compose up -d --wait` — destroys local data; `app/db/schema.sql` auto-runs only on a fresh volume (no migrations) |

Run the test, frontend lint and frontend build commands before a PR. `.github/workflows/ci.yml` runs them on every push/PR against an empty, schema-only PostgreSQL, so data-dependent tests skip there; a green CI does not replace a local run on loaded data.

In the sequences below, bare script names mean `uv run python -m scripts.<name>`:

- **Universe bootstrap, in order:** `fetch_phase0` → `fetch_prices` → `fetch_submissions` → `load_postgres`. For the backtest cohort, append `--manifest data/backtest/companies.json` to each.
- **Full cohort reproduction:** `build_cohort` → manifest bootstrap above → `fetch_form4` → `load_form4` → `backfill_prices` if zero-price targets remain → `uv run python -m app.jobs.nightly` → `backtest`.
- **Broad US-listed candidate universe:** `uv run python -m scripts.build_universe --limit 100 --output data/universe/pilot_000.json`, then the four bootstrap scripts with `--manifest data/universe/pilot_000.json`. The SEC exchange file is only a seed, not proof of active listing; do not overwrite the backtest manifest. `annual_forms` opts into 20-F/40-F extraction; 6-K filings are archived but not treated as 8-K signals.
- `fetch_form4`/`load_form4` have no `--manifest` flag. Nightly only updates Form 4 incrementally for companies that already have Form 4 filings; it does not bootstrap that history.

## Test and job safety

- **Never run the full suite with a hosted/production `DATABASE_URL`.** `test_nightly_fills_signals_and_is_idempotent` runs nightly twice and deletes/reinserts signals in the configured DB; use a local/disposable DB.
- DB-dependent tests in `test_api`, `test_repo` and `test_nightly` skip when PostgreSQL or required data is unavailable. `main(refresh=False)` keeps nightly tests offline, but the full suite is not guaranteed network-free: submission tests can fetch EDGAR on a cache miss.
- Nightly logs per-company failures and continues without a failing exit status; `/health` does not query PostgreSQL. A green Action or health response does not prove data health.

## Architecture and invariants

- Public company/search API routes are read-only. `/me/watchlist` is the user-data write path; trust only Clerk identity verified by Next and the server-only `WATCHLIST_API_SECRET`, never a browser-supplied user ID. The local user UUID is deterministic from Clerk's subject; keep that mapping stable. The 10-company limit is enforced under a per-user row lock in `app/db/repo.py`.
- `app/jobs/nightly.py` remains the only **production writer of `signals`**.
- Tier-change alerts (`app/alerts/`) have no state table: nightly reads the stored latest composite before replacing signals and alerts after commit, so reruns never duplicate. `main(notify=False)` is the default so tests never send e-mail; only the CLI enables it. Never log e-mail addresses (Actions logs may be public).
- Nightly refresh → compute → replaces signals in one transaction per company. Batch loaders write ingestion tables; shared ingestion lives in `app/ingest/`.
- `app/normalize/loader.py` is the single XBRL extraction engine for scripts and nightly; do not duplicate its selection rules. `app/signals/` contains pure functions, `compute.py` their wiring, and `composite.py` the tuned weights.
- Missing required inputs mean `None`/omitted signal, never 0 or an invented fallback. The composite instead averages its **available** components and returns `None` only when none are usable.
- Every non-composite signal needs a source `filing_id`. Composite intentionally has none; trace it through `details.components`.
- `events`, `insiders_rows` and `splits` distinguish `None` (not loaded; omit the signal) from `[]` (checked, none found). Never synthesize `[]`: a false healthy component dilutes the composite.
- Backtest/DL availability is conservative: a point becomes usable at the maximum `filed_at` of all required components/window inputs. Preserve this anti-leakage rule in new metrics.
- Scores are unreliable for banks/insurers/REITs; filter them at display time using `companies.sector_group`, while retaining stored history.
- `frontend/` uses Next 16 Cache Components/partial prefetching and hand-rolled SVG charts, not a chart library.

## Data and model traps

- **XBRL:** the default/backtest extractor uses exact `10-K` + `fp=FY` (not amendments); only universe manifests opt into exact `20-F`/`40-F`. Duration facts span 300–400 days; merge tag variants by `period_end`; instant facts use a per-filing vintage vote—never mix vintages or A = L + SE breaks.
- **Splits and shares:** Yahoo closes are split-adjusted but XBRL share counts are raw; multiply closes by later split factors before combining them. `yahoo.cached_splits` reads the shared price cache without network. Piotroski F7 and dilution must apply the same share-plausibility guards plus split correction.
- **Market cap:** route shares/float through `plausible_shares`/`_float_is_plausible` (100× relative checks + 100,000 floors). Preserve the fallback chain: price ≤14d + dei shares → public float ≤365d → price × weighted shares → `None`.
- **SEC:** `EdgarClient` enforces 0.1 s between requests **per instance** and sends the configured User-Agent; keep aggregate shards under 10 req/s and do not bypass the cache/rate limiter. XOM's official ticker CIK 2115436 is an empty holdco—`verify_known` explicitly falls back to 34088; new resolvers must reuse that fallback. BBBY relies on locked CIK 886158/name because of its post-reorg entity.
- **Phase-0 CSVs:** `fetch_phase0` regenerates `*_ratios.csv`; rerun `fetch_prices` then `compute_z` after touching them. `compute_z` is trio-only, not a cohort/backtest step.
- **Form 4:** exact `form == "4"` only (amendments duplicate originals); non-derivative table only; strip the `xslF345X06/` prefix from `primaryDocument` to get XML rather than XSL HTML.
- **Composite/backtest:** weights are tuned (`late_filing` 1.5, `insider_sales` 0.5, `critical_8k` 0.5, remaining signals 1.0); retuning requires a full sweep against the README baseline. Keep `signal_type <> 'lstm'` in `scripts.backtest.load_signal_rows`; `tune_weights` and `train_lstm` share it.
- **DL artifact:** `data/models/lstm.pt` + `lstm.meta.json` are a pair. `load_artifact` returns `None` when absent or `input_dim` mismatches and nightly skips DL; preserve that behavior and ensure both files are tracked or otherwise supplied to hosted Actions.
- **SHAP:** use `GradientExplainer` on the logit with a zeros baseline (DeepExplainer fails on `pack_padded_sequence`). `_FixedLengthScorer` needs one `lengths` entry per batch row or attributions are badly under-scaled. Attribution belongs only on the latest LSTM signal.

## Deployment

- Follow `docs/DEPLOY.md`. Vercel's root directory is `frontend/`; the Render API image deliberately excludes torch/shap, while the nightly Actions job installs them and runs at 05:30 UTC.
